01

从一个会求导的数字开始

原视频 2:25:52 ↗

The spelled-out intro to neural networks and backpropagation: building micrograd

开场的问题

神经网络训练在底层到底在做什么？他用自己两年前发布的 micrograd 来讲：一个自动求导（autograd）引擎，核心只有约 100 行 Python，在它上面搭的神经网络库“简单得像个笑话”。他的意思是，训练神经网络需要的数学全在这 100 行里，PyTorch 多出来的部分主要是为了效率。

  1. 00:08:08

    先问“导数到底在测什么”，不背公式

    定义 f(x) = 3x² − 4x + 5，把 x 往前推一个很小的 h，看 f 变了多少，再除以 h。x = 3 时斜率是 14，x = −3 时是 −22，在 x = 2/3 处是 0。他刻意不写求导法则，因为没人真的会对神经网络的表达式手写求导。

  2. 00:14:12

    多个输入：d = a·b + c

    分别给 a、b、c 加一点 h，看 d 往哪个方向变、变多少。每个输入都有自己的导数，这就是“梯度”的雏形。

  3. 00:19:09

    写 Value 类，把表达式画成图

    Value 包住一个数，记住自己是由哪几个 Value、通过什么运算得来的。他用 graphviz 把整个表达式画出来，每个格子显示 data 和 grad。下面的图就是照这个样子画的。

  4. 00:32:10

    手动反向传播：从 L 往回一个个填 grad

    每填一个梯度，他都用“给输入加 h、重跑前向”的数值方法核对一遍。链式法则用一个比喻讲：汽车比自行车快 2 倍，自行车比人快 4 倍，那汽车比人快 8 倍。

  5. 00:52:52

    一个神经元

    w·x + b，再过 tanh。他手推 tanh 的局部导数 1 − tanh²，然后把同样的反向过程再走一遍。

  6. 01:09:02

    让反向传播自动化

    每种运算在生成输出时附带一个 _backward 闭包，知道怎么把输出的梯度传回给输入。再对整张图做拓扑排序，倒序逐个调用。

  7. 01:22:28

    现场修 bug：同一个节点被用了两次

    b = a + a 时 a 的梯度应该是 2，代码却给出 1：第二次赋值覆盖了第一次。修法是梯度一律用 += 累加。这也是“每一步训练前要清零梯度”的根源。

  8. 01:27:05

    把 tanh 拆成 exp 和除法

    拆成更原子的运算，得到一模一样的梯度。运算粒度可以自己定，只要写得出它的局部导数。

  9. 01:39:31

    在 PyTorch 里做同一件事

    同样的数字、同样的梯度。PyTorch 把标量换成了张量，数学上没有新东西。

  10. 01:43:55

    Neuron → Layer → MLP，然后训练

    几十行代码搭出 MLP，造一个 4 个样本的小数据集，用平方误差做 loss，手写梯度下降循环。训练中他发现自己忘了在 backward 之前清零梯度，说这是神经网络最常见的错误之一，然后改掉重跑。

带走
  • 神经网络就是一个大数学表达式，loss 是它最后吐出的一个数。
  • 梯度 = 把这个输入往上推一点，loss 会变多少。反向传播 = 链式法则 + 拓扑序，每个节点只需要知道自己的局部导数。
  • 加号把梯度原样分发，乘号把对方的值乘上来；同一个变量被用多次，梯度要累加。
  • 训练循环四步：前向、清零、反向、更新。
02

先数数，再让神经网络学会同样的数

原视频 1:57:45 ↗

The spelled-out intro to language modeling: building makemore

开场的问题

makemore 就是 make more：给它一堆东西，它造出更多类似的。数据是 names.txt，约 32,000 个名字，目标是生成听起来像名字、但并不存在的新名字。他把它叫做字符级语言模型：每个名字都打包了好几个“下一个字符是什么”的例子，比如以某个字母开头的概率、某个字母后面常跟什么、名字通常在哪里结束。

本集和下一集的演示都在浏览器里，用页面内置的 约 500 个常见英文名实时计算，所以数字和视频里不同，规律是一样的。

  1. 00:06:24

    只看前一个字符：bigram

    最简单的语言模型。每个名字前后补一个特殊符号（先是 <S> 和 <E>，后来统一成一个 “.”），然后数每一对相邻字符出现了几次。

  2. 00:12:45

    把计数放进 27×27 的张量，这就是“训练”

    他说这张表就是训练好的模型：模型的全部参数就是这些计数。

  3. 00:24:02

    从表里采样

    从 “.” 那一行出发，按概率抽下一个字符，再去那个字符的行继续抽，直到抽回 “.”。他固定了随机数生成器的种子（2147483647），让观众能得到一样的结果。生成的名字比乱猜好一些，但仍然很烂，因为模型只看一个字符。

  4. 00:36:17

    向量化与广播规则

    每行除以行和就得到概率。他在这里花了很长时间讲 PyTorch 的 broadcasting 规则：漏写 keepdim=True 代码照样能跑，却悄悄变成按列归一化。他建议大家认真读一遍广播的文档。

  5. 00:50:14

    给模型打分：负对数似然

    把训练集里每个 bigram 的概率乘起来就是似然。乘积小到没法用，就取 log 相加；log 是负的，再取负；最后取平均。越低越好，整个训练集上是 2.45。

  6. 01:00:50

    平滑：别让概率等于 0

    他在自己的名字后加个 q，变成 andrejq。jq 从没出现过，概率是 0，loss 变成无穷大。修法：所有计数先加 1。加得越多，模型越接近均匀分布。

  7. 01:02:57

    第二部分：同一个问题，换成神经网络

    字符编码成 one-hot，乘一个 27×27 的权重 W 得到 logits，exp 之后按行归一化。这两步就是 softmax。loss 还是同一个负对数似然。

  8. 01:38:36

    梯度下降，走到同一个答案

    用 PyTorch 自动求导训练 W，loss 降到约 2.45，和计数法一样。随后他点破：one-hot 乘 W 就是取出 W 的一行；W.exp() 学出来的正是计数矩阵；给 W 加平方正则项，效果等同于加假计数。

带走
  • 语言模型 = 给定上文，输出下一个 token 的概率分布。
  • 损失函数 = 平均负对数似然。27 个字符均匀乱猜是 −ln(1/27) ≈ 3.30，后面每一集都会拿这个数做检查。
  • 计数法和神经网络在这里是同一个模型。神经网络的好处是能扩展：上下文一长，计数表会爆炸，神经网络不会。
03

用嵌入向量看更长的上下文

原视频 1:15:39 ↗

Building makemore Part 2: MLP

开场的问题

bigram 只看一个字符，预测很差。想多看几个字符，计数表的大小会随上下文长度指数增长：看 3 个字符就要 27³ ≈ 2 万行，每一行都分不到几个样本。他转向 Bengio 等人 2003 年的论文。

  1. 00:01:48

    读论文：把符号嵌入到向量空间

    论文的词表有 17,000 个词，每个词用一个 30 维向量表示。他复述论文里的例子：训练集里从没出现过 “A dog was running in a ___”，但出现过类似的 “The cat was running in a room”。如果 a 和 the、dog 和 cat 的向量相近，知识就能迁移过去。

  2. 00:09:03

    重建数据集：block_size = 3

    用 3 个字符预测第 4 个。一个滑动窗口把每个名字展开成好几个样本。

  3. 00:12:19

    查表、拼接、隐藏层、输出层

    27 个字符先嵌入到 2 维（为了能画出来）。中间他停下来讲 torch.Tensor 的内部：底层是一维存储，view 只改形状和步长等元数据，不复制内存。

  4. 00:37:56

    先过拟合一个 batch

    只拿 32 个样本训练，loss 能降到很低但不到 0，因为同一个上下文（比如 “...”）后面跟了不同的字符。先确认网络有能力学，再上全量数据。

  5. 00:41:25

    minibatch

    每步随机抽 32 个样本算梯度。梯度不精确，但快得多。他的原则：宁可用近似的梯度多走很多步，也比用精确梯度走几步好。

  6. 00:45:40

    学习率不靠猜

    让学习率在 10⁻³ 到 10⁰ 之间指数增长，每步记录 loss，看谷底在哪。他找到大约 0.1，训练后期再降 10 倍（learning rate decay）。

  7. 00:53:20

    切分 train / dev / test

    80% / 10% / 10%。模型越大越能把训练集背下来，只有在没见过的数据上评估才可信。test 集要很少碰，否则也会被“调参调过拟合”。

  8. 01:00:49

    做实验、画嵌入、采样

    加大隐藏层，把嵌入从 2 维加到 10 维，train 降到 2.17、val 2.2，已经比 bigram 的 2.45 好。把 2 维嵌入画出来，元音 a e i o u 聚在一起，说明网络学到它们“可以互换”。

带走
  • 嵌入：离散符号 → 可学习的向量。相似的符号会学到相近的向量，这让模型能泛化到没见过的组合。
  • 超参数：嵌入维度、隐藏层大小、上下文长度、学习率、batch 大小。调参看 val，不看 train。
  • 训练前的固定动作：先过拟合一个小 batch，再做学习率扫描。
04

盯住激活值和梯度的统计

原视频 1:55:57 ↗

Building makemore Part 3: Activations & Gradients, BatchNorm

开场的问题

大家都想赶紧学 RNN、LSTM，他偏要在 MLP 上多停一集。理由：RNN 表达能力很强，但用一阶梯度方法很难优化，原因就藏在训练中激活值和梯度的分布里。不先理解这些，就看不懂后来的架构为什么那样设计。

  1. 00:04:19

    第一个问题：初始 loss 是 27

    刚初始化的网络应该什么都不懂，给 27 个字符差不多的概率，loss 应该约 3.29。实际是 27，说明网络“自信地错了”：某些 logits 特别大。把输出层权重缩小、偏置置 0 就好了，loss 曲线开头的“曲棍球棒”也随之消失，那段时间原本只是在把权重压小。

  2. 00:12:59

    第二个问题：tanh 饱和

    画出隐藏层输出的直方图，大量值贴在 ±1。tanh 在那里的导数 1 − t² 接近 0，梯度传不过去。再画一张黑白图：如果某个神经元对所有样本都饱和，它就是 dead neuron，永远学不动。

  3. 00:27:53

    魔法数字从哪来：Kaiming 初始化

    上一步的缩放系数是手调的。他推导：要让输出的方差保持为 1，权重要除以 √fan_in；遇到 tanh 这种会把数据往里挤的非线性，还要乘一个增益，tanh 的增益是 5/3。他又演示了没有非线性的情况：纯线性网络里增益 1 就刚好。

  4. 00:40:40

    BatchNorm：干脆直接标准化

    既然希望每层的 pre-activation 接近单位高斯，那就在训练时用 batch 的均值和标准差把它标准化，再加上可学习的缩放和平移。它把同一个 batch 里的样本耦合在了一起，带来抖动和正则化效果，也带来很多麻烦。他说没人喜欢这一层，但它确实让深网络好训练多了。

  5. 01:04:50

    读 ResNet-50 的代码

    卷积 → BatchNorm → ReLU 的重复结构到处都是。卷积层不带偏置，因为 BatchNorm 会把它减掉，加了也白加。

  6. 01:18:35

    “开玩笑的，还有第二部分”

    把代码重构成 Linear、BatchNorm1d、Tanh 类，接口模仿 torch.nn。堆 5 层，看四张诊断图：前向激活直方图、反向梯度直方图、参数梯度分布、更新量和参数的比值随时间的变化。他说更新量约为参数的千分之一（log10 约 −3）比较健康。

带走
  • 初始化的目标：让每一层的激活和梯度都保持差不多的尺度。
  • 先算期望的初始 loss。看到 27 而不是 3.3，就知道哪里错了。
  • BatchNorm 让深网络对初始化没那么敏感。第 7 集的 LayerNorm 是同一个想法，只是换了归一化的方向。
  • 训练时多画图：饱和比例、梯度分布、更新量与参数之比。

原视频 1:55:24 ↗

Building makemore Part 4: Becoming a Backprop Ninja

开场的问题

他想删掉 loss.backward() 这一行，在张量层面把反向传播完整手写一遍。理由来自他的一篇博客：反向传播是一个“有漏洞的抽象”（leaky abstraction）。不能把可微分的积木随便堆起来就指望它工作，梯度会饱和、消失、爆炸，不理解内部就没法调。

  1. 00:00:00

    一点历史

    2006 年 Hinton 和 Salakhutdinov 发表在 Science 上的论文，梯度是手写的。2010 年前后他自己写的受限玻尔兹曼机代码用 MATLAB，也是手写梯度。2014 年他的 Deep Fragment Embeddings 论文同样手推梯度并做了梯度检查。他的感慨：以前大家都手写反向传播，现在只调 loss.backward()，丢掉了一些东西。

  2. 00:13:01

    练习 1：一行一行往回推

    前向被拆成 20 来行最原子的操作，包括 BatchNorm 的每一个小步骤。然后从 loss 开始逐行往回，求出每个中间变量的梯度，每一步都用 cmp() 和 PyTorch 的结果比对。

  3. 00:24:40

    形状就是线索：求和与广播的对偶

    前向里一个 [32,1] 的变量被广播到 [32,27]，说明它被复用了，反向就要沿那一维求和；前向求和，反向就广播回去。矩阵乘法的反向也不用背，按形状把转置和乘法拼对就行。

  4. 01:05:17

    插曲：Bessel 校正

    BatchNorm 论文训练时用除以 n 的有偏方差，推理时用除以 n−1 的无偏方差。他觉得这种训练和推理不一致本身就是个 bug，所以统一用 n−1。

  5. 01:26:31

    练习 2：交叉熵一次求完

    不再逐行推，直接对 softmax + 负对数似然整体求导，结果非常简洁：dlogits = softmax(logits) − one_hot(y)，再除以 n。他给的直观解释是一组力：错误字符的概率被往下拉，正确字符被往上推，一行加起来为 0。

  6. 01:36:37

    练习 3：BatchNorm 一次求完

    在纸上推出 BatchNorm 反向的完整公式，压成一行代码：dhprebn = bngain*bnvar_inv/n * (n*dhpreact − dhpreact.sum(0) − n/(n−1)*bnraw*(dhpreact*bnraw).sum(0))。

  7. 01:50:02

    练习 4：全部拼起来

    完全不用 loss.backward()，用手写梯度训练整个 MLP，结果和自动求导一样。本页第 3、4 集的训练演示也是这样写的：浏览器里没有 PyTorch，梯度都是手写的。

带走
  • 反向传播的每一步都是“上游梯度 × 局部导数”，变量被复用就累加。
  • 先看形状：梯度的形状一定和变量本身相同，这能帮你拼出大部分公式。
  • 交叉熵的梯度 = 预测概率 − 真实标签。

让上下文一层层融合

原视频 0:56:21 ↗

Building makemore Part 5: Building a WaveNet

开场的问题

这一集在京都的酒店房间录。目标：输入从 3 个字符扩到 8 个，但不要一次全塞进一个隐藏层，那样“太快地挤压了太多信息”。他要做的结构很像 DeepMind 2016 年的 WaveNet，那篇论文本来是用来生成音频的。

  1. 00:06:56

    先把 loss 曲线画清楚

    单步 loss 噪声太大，把每 1000 步取平均再画，曲线清楚多了，学习率衰减那一下的效果也看得出来。

  2. 00:09:16

    继续 PyTorch 化

    加 Embedding、Flatten 和 Sequential 容器，训练代码缩到几行。顺带讲了几个因为 BatchNorm 训练/推理模式没切换导致的 bug。

  3. 00:19:33

    最简单的改动：上下文 3 → 8

    只改 block_size，val loss 从 2.10 降到 2.02。

  4. 00:21:36

    实现分层融合

    新写一个 FlattenConsecutive：相邻两个字符先融合，再两两融合，三层后看到全部 8 个字符。关键观察：PyTorch 的矩阵乘只作用于最后一维，前面所有维度都被当成 batch，所以这棵树可以一次性算完。

  5. 00:38:50

    抓 bug：BatchNorm1d 收到了三维输入

    代码能跑，结果不对。他是从 running_mean 的形状不对发现的。

  6. 00:46:07

    放大

    约 76,000 个参数，val loss 1.993，第一次跌破 2.0。代价是训练明显变慢。

  7. 00:47:44

    dilated causal convolution 只是实现细节

    论文里吓人的名字，本质是把这棵树沿序列滑动的 for 循环搬进 CUDA kernel，同时复用相邻位置共享的中间节点。模型本身和他写的是一回事。

  8. 00:52:28

    真实的开发流程

    大量时间花在读文档、对张量形状上；先在 notebook 里试，再搬回仓库代码。他也承认这一集缺少实验框架：没有系统的超参搜索，只是凭感觉调。

带走
  • 架构设计的一个原则：信息逐层融合，不要过早压缩。
  • 每加一点复杂度都和 baseline 比，并控制参数量相同，才知道改动本身有没有用。
  • 三维张量过 BatchNorm 时，要想清楚统计量沿哪些维度算。

自注意力：让 token 互相交流

原视频 1:56:20 ↗

Let's build GPT: from scratch, in code, spelled out.

开场的问题

他让 ChatGPT 写一首俳句，同一个提示两次生成的结果不同：它是一个概率系统，从左到右逐个生成 token。它背后是 2017 年论文 Attention Is All You Need 提出的 Transformer。从零训练 ChatGPT 做不到，但可以在 1MB 的 Tiny Shakespeare 上从零写一个字符级 Transformer，也就是他的 nanoGPT 的简化版。

  1. 00:09:28

    tokenizer 与 train / val 切分

    字符级：65 种字符各对应一个整数。他提到 Google 的 SentencePiece、OpenAI 的 tiktoken 用的是子词：词表更大，序列更短。这里为了简单用字符。前 90% 做训练，后 10% 做验证。

  2. 00:14:27

    一块数据里藏着 8 个样本

    随机截一段长度为 block_size + 1 的文本，输入和目标错开一位。上下文长度从 1 到 8 的样本都在里面，这样模型推理时也能从很短的上下文开始生成。

  3. 00:22:11

    最简单的基线：bigram

    一个 nn.Embedding(65, 65) 直接查出下一个字符的 logits。训练后 loss 约 2.5，生成的文字有莎士比亚的“形状”，内容全是胡话。

  4. 00:42:13

    数学技巧：用矩阵乘法做加权平均

    想让每个 token 和它之前的 token 交流，最弱的方式是取平均。他连写三个版本：for 循环、下三角矩阵乘法、masked_fill 加 softmax，结果完全一样。第三个版本已经是 attention 的形状。

  5. 01:02:00

    视频的核心：self-attention

    平均是一视同仁，但不同 token 对过去的兴趣不同，他举的例子是元音可能在找前面的辅音。每个 token 发出两个向量：query（我在找什么）和 key（我有什么），两者点积就是亲和度。还有 value：如果你对我感兴趣，我告诉你这个。

  6. 01:11:38

    关于 attention 的 6 条笔记

    ① 它是有向图上的通信机制；② 它没有空间概念，只是在一组向量上操作，所以要另加位置编码；③ batch 里不同样本之间不通信；④ encoder 不加三角 mask，decoder 加；⑤ self-attention 和 cross-attention 的区别只在 key、value 从哪来；⑥ 要除以 √head_size。

  7. 01:21:59

    搭出完整的 Transformer 块

    多头注意力 → 前馈层 → 残差连接 → LayerNorm，每加一个部件报一次 val loss。前馈层的隐藏维度照论文放大 4 倍。

  8. 01:37:49

    放大

    384 维、6 个头、6 层、上下文 256、dropout 0.2，在 A100 上训练约 15 分钟，val loss 1.48。生成的文字已经很像莎士比亚的格式，只是读不通。

  9. 01:42:39

    我们写的是 decoder-only

    原论文是 encoder-decoder，用于机器翻译：encoder 读法语，decoder 通过 cross-attention 读 encoder 的输出。GPT 只有 decoder，所以没有 cross-attention。

  10. 01:48:53

    回到 ChatGPT

    我们做的只是预训练。ChatGPT 还要经过监督微调、奖励模型、PPO 强化学习，这些数据不公开。下一个视频（第 8 集）讲这条流水线。

带走
  • attention = 由数据决定权重的加权平均。mask 决定能看谁，softmax 保证权重和为 1。
  • self-attention 里 Q、K、V 都来自同一个 x；它本身不知道顺序，位置编码要另外加。
  • Transformer 块 = 通信（attention）+ 计算（MLP），残差和 LayerNorm 让深网络能训练。

GPT 助手怎么炼成，又该怎么用

原视频 0:42:40 ↗

State of GPT · Microsoft Build 2023

开场的问题

这是他 2023 年在微软 Build 大会上的演讲，不写代码。上半场讲 GPT 助手的训练流程，下半场讲怎么把它用好。

  1. 00:00:46

    四个阶段

    预训练 → 监督微调 → 奖励建模 → 强化学习，前一阶段的产出是后一阶段的起点。

  2. 00:02:20

    预训练的规模

    数据混合、tokenization、超参。他拿 LLaMA 65B 和 GPT-3 175B 比：参数少得多，却更强，因为训练了 1.4 万亿 token，而不是 3000 亿。他的原话：不要只看参数量判断模型的能力。

  3. 00:09:09

    基座模型不是助手

    它只想补全文档。GPT-2 时代人们发现，把任务排成一篇“假文档”（few-shot：问答、问答、问答，最后只给问题）就能骗它答题。

  4. 00:17:43

    为什么 RLHF 有效

    评判比生成容易：让承包商写一首关于回形针的俳句很难，但从几首里挑出好的很容易。代价是 RLHF 模型的熵变低，输出更单一。

  5. 00:20:26

    你的大脑 vs 它的“大脑”

    他用一个例子：你写 “California’s population is 53 times that of Alaska” 这句话之前，脑子里发生了一大串事情。GPT 只看到最终的 token 序列，每个 token 分到的计算量都一样。

  6. 00:24:45

    Transformer 需要 token 来思考

    不能指望它在一个 token 里做完复杂推理。办法：让它一步一步写出过程，多采样几次挑好的，让它检查自己是否完成了任务，用 Tree of Thought 这类搜索。他把这些统称为给 LLM 补上 System 2。

  7. 00:30:02

    LLM 不想成功，它只想模仿

    训练数据里好答案、烂答案都有，它默认全都模仿。所以要明确要求高质量：“让我们一步步推理，确保答案正确”，“你是这个领域的顶尖专家”。但别要 IQ 400，那会跑出训练分布，甚至跑进科幻小说里。

  8. 00:31:59

    工具、检索、约束、微调

    告诉它自己不擅长心算，去用计算器、代码解释器；把相关文档检索出来放进上下文（它的工作记忆）；用约束采样强制输出 JSON；LoRA 等方法让微调变得可行。但 RLHF 仍是研究领域，他不建议自己做。

  9. 00:37:11

    他的默认建议

    先追求最好的效果：用最强的模型（当时是 GPT-4），写详细的提示，给示例，加检索和工具；之后再优化成本。用在低风险场景，保留人工监督，把它当副驾驶，而不是自主代理。

带走
  • 预训练占约 99% 的算力，产出的是文档补全器；后面三个阶段把它调成助手。
  • 每个 token 的计算量是固定的，难的推理需要更多 token。
  • 提示工程很大程度上是在弥补人脑和 Transformer 之间的认知差异。

Tokenizer：很多怪毛病的源头

原视频 2:13:34 ↗

Let's build the GPT Tokenizer

开场的问题

他说 tokenization 是他最不喜欢的部分，但绕不开：LLM 拼不对单词、算不好算术、处理非英语更差、问到 “SolidGoldMagikarp” 就开始胡言乱语、提示末尾多一个空格就收到警告，这些毛病大多能追到 tokenization 上。

  1. 00:05:50

    在 tiktokenizer 网页里看例子

    “egg” 在句首、句中、首字母大写时是不同的 token；数字有时是一个 token，有时被拆开；韩语、中文要用更多 token；GPT-2 把 Python 缩进里的每个空格单独算一个 token，浪费上下文，GPT-4 的分词器把空格合并了。

  2. 00:14:56

    字符串、Unicode、UTF-8

    Python 字符串是 Unicode 码点的序列。码点有约 15 万个而且还在增加，不适合直接当词表。UTF-8 把每个码点编成 1 到 4 个字节，对 ASCII 最省，所以选它。

  3. 00:22:47

    幻想：干脆不要 tokenizer

    直接喂字节，词表只有 256，但序列太长，注意力的上下文很快用完。他希望将来能做到，眼下需要压缩。

  4. 00:23:50

    BPE：反复合并最常见的相邻对

    先用维基百科上的例子 aaabdaaabac 手算一遍，再写代码：get_stats 数相邻对，merge 替换，while 循环一直合并到想要的词表大小。

  5. 00:39:20

    tokenizer 是完全独立的一个阶段

    它有自己的训练集，训练完就冻结，LLM 只看到 token id。tokenizer 的训练数据里某种语言越多，那种语言的合并就越多，用的 token 就越少。

  6. 00:57:36

    GPT-2 的正则：合并不跨类别

    OpenAI 先用正则把文本切块，字母、数字、标点、空白分开，BPE 只在块内合并。不然 “dog.” “dog!” “dog?” 会各自占一个词表位置。

  7. 01:18:26

    特殊 token 与词表大小

    GPT-2 的词表 50,257 = 256 个字节 + 50,000 次合并 + 1 个 <|endoftext|>。词表太大，嵌入层和输出层变大，每个 token 被训练到的次数变少；太小，序列变长。

  8. 01:28:42

    SentencePiece（Llama 2 在用）

    它在码点上做 BPE，罕见码点退回字节（byte fallback）。他觉得它配置项太多、历史包袱重，但很多开源模型在用，所以要会。

  9. 01:51:41

    回头解释那些怪毛病

    拼写和数字母“.DefaultCellStyle” 在 GPT-4 里是一个 token，模型看不到里面的字母。
    非英语更差tokenizer 训练数据以英语为主，同样意思的韩语、中文要更多 token，上下文更快用完。
    算术数字被任意切分，同样四位数可能是一个 token，也可能被拆成两段，位数对不齐。
    GPT-2 写 Python每个缩进空格单独一个 token，上下文被大量浪费。
    末尾空格警告训练数据里空格通常和后面的词粘在一起（“␠egg”），提示以空格结尾时，模型落在一个很少见的状态。
    SolidGoldMagikarp一个 Reddit 用户名，在 tokenizer 的训练数据里频繁出现，被合并成一个 token；但 LLM 的训练数据里几乎没有它，这个 token 的嵌入从没被训练过，一用就出怪事。
    YAML 比 JSON 省他的例子里同样的数据，JSON 用 116 个 token，YAML 用 99 个。
带走
  • LLM 看到的是 token id，不是字符。很多“它连这都不会”的问题，是因为它根本看不到你以为它看到的东西。
  • BPE = 在 UTF-8 字节上反复合并最常见的相邻对。
  • tokenizer 和模型分开训练，它的训练数据决定了哪种语言、哪种格式更“便宜”。

复现 GPT-2 (124M)

原视频 4:01:26 ↗

Let's reproduce GPT-2 (124M)

开场的问题

2019 年 OpenAI 发布 GPT-2 时，训练它是个大工程。他说今天在云上租一台机器，大约一小时、10 美元左右就能复现 124M 的版本。这一集 4 小时，分四部分：搭模型、让它变快、照论文设超参、看结果。

  1. 00:03:39

    先看 OpenAI 的权重

    用 HuggingFace 加载 GPT-2，打印每个张量的形状：词嵌入 50257×768，位置嵌入 1024×768。把位置嵌入画出来，能看到正弦、余弦状的曲线，这是训练学出来的，不是写死的。

  2. 00:13:47

    照着权重的名字写自己的 GPT

    结构和第 7 集基本一样，区别是 LayerNorm 前置、激活函数换成 GELU。他把 attention 比作 reduce（在 token 之间汇总信息），MLP 比作 map（每个 token 各自处理），Transformer 就是反复的 map-reduce。加载 OpenAI 的权重后生成的句子通顺，说明实现对了。

  3. 00:45:50

    开始训练：先检查初始 loss

    50,257 类均匀分布的 loss 应为 −ln(1/50257) ≈ 10.82，实测约 11，对得上。然后先过拟合一个 batch。

  4. 01:06:14

    共享 wte 和 lm_head

    GPT-2 原版的做法：输入嵌入和输出层用同一个矩阵。

  5. 01:13:47

    初始化

    照 GPT-2 的源码，标准差用 0.02。残差路径上的投影层再乘 1/√(2·层数)：每层都往残差流里加两次东西，不缩放的话方差会越加越大。他用一个小实验演示了这种增长。

  6. 01:22:18

    第二部分：让它变快

    从每步 1000 毫秒降到 90 毫秒。

  7. 02:14:55

    第三部分：照 GPT-3 论文设超参

    GPT-2 论文的训练细节写得很少，他转而参考架构相近、写得更详细的 GPT-3 论文：AdamW、梯度裁剪、学习率预热加余弦衰减、weight decay 只作用于二维参数。

  8. 02:34:09

    梯度累积与多卡训练

    0.5M token 的 batch 一张卡放不下，就分多次累积；8 张卡用 DDP 并行。

  9. 03:10:21

    数据与评测

    训练数据用 HuggingFace 的 FineWeb-Edu（教育类网页）的 100 亿 token 样本；留出验证集；用 HellaSwag 做评测，这是一个四选一的常识补全题库。

  10. 03:43:05

    第四部分：第二天早上看结果

    在 FineWeb-Edu 的验证集上 loss 低于 OpenAI 的 GPT-2 124M，HellaSwag 也超过了它。

  11. 03:56:21

    llm.c

    他的另一个项目：用纯 C/CUDA 写同样的训练，不依赖 PyTorch，跑得更快。

带走
  • 复现一个模型的顺序：先对齐结构和权重，确认能生成合理文本，再从头训练。
  • 速度主要卡在内存搬运，而不是计算。降精度、编译、算子融合、FlashAttention、凑整齐的数字，都在减少内存读写。
  • 论文没写清楚的细节，就去读它的源码，或者参考写得更详细的相近论文。

  • 从空白 notebook 写起
